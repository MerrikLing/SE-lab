## 二、视觉系统

**方向：Riso 票根 / 城市活动印刷海报**
**适用范围：城市与社区的活动、演出、讲座、市集等通用票务场景，不限于校园。**

- 色彩：纸色 `#F5EFE3`、纸白 `#FFFCF5`、墨黑 `#151515`、信号蓝 `#2447FF`、荧光橙 `#FF4D00`、薄荷绿 `#B9F2C9`
- 字体：展示 `Bahnschrift` + 微软雅黑；正文 `Segoe UI` + 微软雅黑；数据/标签 `Cascadia Mono` / Consolas
- 布局：226px 左侧栏 + 主内容；12 栏网格；1440×900
- 签名元素：**票根齿孔 + 场次编号条 + 条码**。每张活动/场次卡都是票根：左侧 stub 放编号、日期、条码，中间虚线齿孔，右侧放内容；状态用轻微旋转的印章。
- 第 4 屏（检票员）刻意反转为墨黑底 + 薄荷绿扫描信号，对应「闸口/夜间现场」的使用场景；其余四屏保持纸色底。
- 所有图形为 CSS/内联 SVG，无外部图片、无联网字体；离线也能渲染。

## 四、与设计的一致性

- 报名页显示「场次 + 票种 + 剩余名额 + 候补」，并注明「同一场次每位参与者限 1 张；重复提交返回原结果」。
- 组织者页的流水线是「草稿 → 待审核 → 已发布 → 已结束」，对应活动状态机；「发布检查」列出容量 ≥ 已报名、至少 1 场次 1 票种。
- 检票页的「签到成功 / 重复扫码 / 非本场次」对应 REQ-011；补签是独立入口，不在扫码页直接改状态。
- 管理员页的「通过并发布 / 退回修改 / 强制下架」对应 REQ-003；下架不改变活动状态，只写审计。
- 所有页面只表达交互与信息层级，不包含真实业务逻辑；UI 中的示例数据仅用于展示。
