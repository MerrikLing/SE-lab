## 1. 架构与依赖规则

```
驱动适配器（Web/UI、定时器、CLI）
        │ 只依赖 application 的 Command/DTO
应用层（15 个应用服务：权限、事务、编排、幂等、审计埋点）
        │ 只依赖 domain + application.ports
领域层（实体、值对象、状态机、规则对象；零 I/O，now 显式传入）
        ▲ 端口由外层实现
被驱动适配器（SQLite 仓储/UoW/席位账本、HMAC 二维码、PBKDF2、站内通知、模拟支付、CSV/XLSX、时钟、备份）
composition/ 装配根：唯一 import 三层的地方；权限规则表在这里集中声明
```

硬规则：
1. `domain` 不 import 任何外层或第三方库。
2. `application` 不 import `adapters`/`infrastructure`。
3. 跨模块只通过公开应用服务、端口、`shared` 的 DTO/事件交互；禁止 import 对方领域实体。
4. 领域方法必须接收 `now: datetime`；禁止 `datetime.now()` 出现在领域层。
5. 所有 `datetime` 为**带时区 UTC**；适配器负责与本地时区互转；数据库存 ISO-8601 UTC。
6. 一个用例一个事务边界；事务内不调用外部网络（模拟支付/二维码签名均为本地）。
7. `shared` 只放"被两个以上模块依赖、且不含业务规则"的契约；业务规则一律进领域模块。
8. **任何字段只能有一个写者**：跨聚合/跨模块写入必须显式声明归属；`save` 不得整行覆盖由原子操作维护的字段。
9. **UoW 是环境式的**（contextvar 或显式注入的同一个 `UnitOfWork`）：`RegistrationInvalidationPort` 等跨模块端口必须加入调用方事务，不得自行提交。

## 2. 八个业务模块与依赖 DAG

| # | 模块 | 职责 | 拥有的聚合/实体 | 明确不做 |
|---|---|---|---|---|
| M0 | `shared` | ID 类型、枚举、`ActorContext`、`AccessContext`、`Page`、错误体系、领域事件 DTO、`AuditPort`、`AuditQueryPort`、`OutboxPort`、`Clock`、`UnitOfWork`、`OperationsReadPort`、`RegistrationInvalidationPort` | 无 | 不含业务规则 |
| M1 | `identity` | 注册登录、密码/锁定、四角色、组织者申请审批、场次检票授权、黑名单、`AccessPolicy` | `User`、`AuthSession`、`OrganizerApplication`、`BlacklistEntry`、`SessionAssignment` | 不判断活动业务状态；不存报名 |
| M2 | `catalog` | 活动/场次/票种、审核、发布、下架、修改重审、取消、自动结束、查询、**名额账本** | `Event`、`EventSession`（含 `TicketType`） | 不存报名明细；不发通知；不做统计 |
| M3 | `registration` | 报名、代报名、幂等、候补、取消、递补、失效、票证内容 | `Registration`（含 `CheckIn`） | 不决定有没有名额（问 `SeatInventoryPort`）；不签二维码（端口） |
| M4 | `attendance` | 扫码验签、签到、补签、缺席结算、场次/活动结束收尾 | 无独立聚合；操作 `Registration.check_in` | 不拥有报名状态机；不改名额 |
| M5 | `social` | 评价、收藏、举报与处理；拉黑只调 `AccessRepository` | `Evaluation`、`Report`、`Favorite` | 不拥有黑名单实体；不直接下架（调 catalog） |
| M6 | `notification` | 站内消息、事件→消息映射、去重、开票提醒 | `NotificationMessage` | 不 import 任何业务模块；只消费事件与 `OperationsReadPort` |
| M7 | `reporting` | 名单导出（脱敏/完整审批）、容量与参与率统计 | `ExportRequest` | 不写业务表；不加载聚合做展示 |
| M8 | `audit` | 关键操作日志只追加、检索、≥365 天保留（归档） | `AuditEntry` | 不参与业务决策；不阻塞成功路径 |

依赖 DAG（`A --> B` 表示 A 依赖 B）：

```
shared                 （无依赖）
identity   --> shared
audit      --> shared
catalog    --> identity, shared
registration --> catalog, identity, shared
attendance --> registration, catalog, identity, shared
social     --> registration, catalog, identity, shared
reporting  --> catalog, registration, identity, shared
notification --> shared
```

拓扑序：`shared → identity → audit → catalog → registration → attendance → social → reporting → notification`。

反向依赖：
- `catalog` 取消活动 → `shared.RegistrationInvalidationPort`（`registration` 实现，加入调用方 UoW）。
- `notification` → `shared.OperationsReadPort`（SQL 适配器实现；不 import 业务模块）。
- `social` → `registration` 的 `exists_checked_in` 只读方法；方向允许。
- 业务模块 → `shared.AuditPort`；不 import `audit` 模块。

## 3. 聚合与不变式

| 聚合根 | 聚合内实体/值对象 | 关键不变式 |
|---|---|---|
| `User` | 角色集合、锁定状态 | 密码哈希；5 次失败锁 15 分钟；角色授予 |
| `AuthSession` | — | 30 分钟闲置失效 |
| `OrganizerApplication` | — | 审批一次，不可覆盖 |
| `BlacklistEntry` | — | `(organizer_id, participant_id)` 唯一 |
| `SessionAssignment` | — | `(session_id, inspector_id)` 唯一；`revoked_at` 为空才有效 |
| `Event` | `Visibility`、审核结论字段 | 状态机；下架不改 status；实质性修改回重审；起止时间由场次派生 |
| `EventSession` | `TicketType` | `booked_count <= capacity`；`ticket_type.sold <= quota`；`next_waitlist_no` 唯一递增 |
| `Registration` | `CheckIn`（0..1）、支付状态、票证 nonce | 六状态机；`(session_id, participant_id)` 有效态唯一；一报名一签到 |
| `Evaluation` | — | `(session_id, participant_id)` 唯一；无 update |
| `Report` | — | 处理结论一次 |
| `Favorite` | — | `(user_id, event_id)` 唯一 |
| `NotificationMessage` | — | `(user_id, type, dedupe_key)` 唯一 |
| `OutboxMessage` | — | 投递幂等；`published_at IS NULL` |
| `ExportRequest` | — | FULL 导出必须 approved |
| `AuditEntry` | — | 只追加；保留 ≥365 天（归档，不删） |

**唯一账本规则（关键）**：
- `EventSession.booked_count`、`next_waitlist_no`、`TicketType.sold_count` 的**唯一写入者**是 `SeatInventoryPort` 的原子操作。
- `EventSessionRepository.save_metadata()` 只写元数据（时间、地点、票种名称/价格/配额），**禁止写** `capacity`、`booked_count`、`next_waitlist_no`、`sold_count`；实现采用显式列清单，不做整行 UPDATE。
- 容量修改只走 `SeatInventoryPort.resize(session_id, new_capacity)`。
- `EventSession.booked_count` 仅作只读快照；`remaining_snapshot()` 仅展示，不用于判定。
- 取消活动时 `SeatInventoryPort.reset(session_id)` 将 `booked_count` 与各票种 `sold_count` 归零；历史由报名记录与审计保留。
- `Registration` 的状态与 `CheckIn` 由 `RegistrationRepository.save()` 写入，带 `version` 条件；`SeatInventoryPort` **不写** `registration` 行。

数据库兜底：
- `CHECK (booked_count <= capacity)`；`CHECK (sold_count <= quota)`。
- 部分唯一索引 `(session_id, participant_id) WHERE status IN ('WAITLISTED','REGISTERED','CHECKED_IN','ABSENT')`。
- `UNIQUE(session_id, waitlist_no)`；`UNIQUE(registration_id)` on `check_in`。
- `UNIQUE(user_id, type, dedupe_key)` on `notification_message`。
- `UNIQUE(session_id, participant_id)` on `evaluation`。
- `UNIQUE(actor_id, scope, key)` on `idempotency_record`。
- 外键 + `PRAGMA foreign_keys=ON`；SQLite 建议 `journal_mode=WAL`。

### 5.2 技术/扩展端口

```python
class SeatInventoryPort(Protocol):
    # 所有操作对同一 session 行原子、线性；成功次数永不超过容量
    def claim(self, session_id: EventSessionId, ticket_type_id: TicketTypeId,
              now: datetime) -> SeatClaim: ...
    def release(self, session_id: EventSessionId, ticket_type_id: TicketTypeId) -> bool: ...
    # 只调整席位/票种计数，不写 registration；booked 不变，outgoing.sold--，incoming.sold++
    # seat_no 直接继承被取消记录的 seat_no（不重新发号）
    def reserve_for_promotion(self, session_id: EventSessionId,
                              outgoing_ticket_type_id: TicketTypeId,
                              incoming_ticket_type_id: TicketTypeId,
                              outgoing_seat_no: int,
                              now: datetime) -> SeatClaim: ...
    # 条件 UPDATE：new_capacity >= booked_count；返回 False 表示容量不足/并发冲突，调用方重读后重试或提示
    def resize(self, session_id: EventSessionId, new_capacity: int) -> bool: ...
    def reset(self, session_id: EventSessionId) -> None: ...
    def snapshot(self, session_id: EventSessionId) -> SeatSnapshot: ...
```

`reserve_for_promotion` 适配器契约：
1. 先锁 `event_session` 行（`SELECT ... FOR UPDATE` / SQLite `BEGIN IMMEDIATE` + 条件 UPDATE）。
2. 校验场次未结束（`now <= end_at` 且 `settled_at is None`）；否则 `SESSION_CLOSED`。
3. 校验 incoming 票种 `sold < quota`；否则 `TICKET_TYPE_FULL`。
4. `booked_count` 不变；`outgoing.sold -= 1`，`incoming.sold += 1`。
5. 返回 `SeatClaim(GRANTED, seat_no=outgoing_seat_no)`；座位号直接继承被取消记录，不重新发号；**不 UPDATE registration**。
6. 报名状态由 `RegistrationService` 在同一 UoW 内 `candidate.promote(seat_no)` + `RegistrationRepository.save`（version 条件）写入。

`resize` 契约：`UPDATE event_session SET capacity = ? WHERE id = ? AND ? >= booked_count`；`rowcount=1` 返回 `True`；否则 `False`（调用方重读 `snapshot` 后提示“容量不得小于已报名数”或重试）。

### 6.13 通知事件→消息映射（REQ-018）

`NotificationService.handle_event(event, now)` 按 `event.event_type` 查表；`payload` 为扁平字符串。

| 事件 | NotificationType | 收件人 | 标题 | 正文模板 | dedupe_key |
|---|---|---|---|---|---|
| `RegistrationConfirmed` | `REGISTRATION_SUCCESS` | `participant_id` | 报名成功 | 你已成功报名《{event_title}》，场次 {session_time}，票种 {ticket_type}。 | `registration:{registration_id}:success` |
| `RegistrationPromoted` | `WAITLIST_PROMOTED` | `participant_id` | 候补成功 | 你已从候补转为正式报名《{event_title}》，座位号 {seat_no}。 | `registration:{registration_id}:promoted` |
| `EventCancelled` | `EVENT_CANCELLED` | `OperationsReadPort.event_affected_user_ids(event_id)` 的每个用户 | 活动已取消 | 你报名的《{event_title}》已取消，费用已按模拟支付规则退款。 | `event:{event_id}:cancelled:{user_id}` |
| `ReviewDecided` | `REVIEW_RESULT` | `organizer_id` | 审核结果 | 《{event_title}》审核{通过/不通过}：{comment}。 | `event:{event_id}:review:{revision}` |
| `ReportResolved` | `REPORT_RESOLVED` | `reporter_id` | 举报处理结果 | 你对《{event_title}》的举报已处理：{result}。 | `report:{report_id}:resolved` |
| 开票提醒（定时任务生成） | `SALE_REMINDER` | 收藏者 | 开票提醒 | 你收藏的《{event_title}》将于 {sale_start_at} 开售。 | `event:{event_id}:sale:{user_id}` |

生成规则：
1. `handle_event` 先查 `exists_dedupe`；命中则跳过。
2. 写 `NotificationMessage`（`type`、`payload`、`dedupe_key`）；唯一约束兜底。
3. 发送失败由 `OutboxRelay` 重试；消息表本身已落库，不丢。
4. `EventCancelled` 的收件人由 `OperationsReadPort.event_affected_user_ids` 提供；不把大批用户 ID 放进事件 payload。

## 7. 关键交互流程

### 7.1 报名（幂等 + 满员候补 + 取消递补）

1. `Web` 解析 `Idempotency-Key`、`ActorContext`；`cmd.beneficiaries` 长度 1~3。
2. `RegistrationService.register`：
   1. `IdempotencyStore.get(actor.user_id, "register", key)`：
      - 命中 `COMPLETED` 且 `request_hash` 相同 → 直接返回原结果（`replayed=True`）；**先回放，避免用户后来被拉黑导致原结果不可见**。
      - 命中但 hash 不同 → `IdempotencyConflict`。
   2. 加载活动/场次；对每个受益人构建 `AccessContext`（`participant_id` + `is_blacklisted` + `is_event_visible`）；`AccessPolicy.require(REGISTER)`；`Event.assert_registrable`、`EventSession.assert_accepting`。
   3. `[TX]` 对每个受益人：
      - `find_active(session, participant)` 命中 → 该受益人返回 `ALREADY_REGISTERED`，不新增；
      - `SeatInventoryPort.claim(session, ticket_type, now)`：
        - `GRANTED` → `Registration.create_confirmed(..., seat_no=claim.seat_no)`；
        - `SESSION_FULL` / `TICKET_TYPE_FULL` → `Registration.create_waitlisted(..., waitlist_no=claim.waitlist_no)`，`payment_status=PAID`，`payment_ref="sim:{id}"`；
        - `SESSION_CLOSED` → 该受益人失败。
      - `RegistrationRepository.add`；`OutboxPort.enqueue(...)`。
   4. `IdempotencyStore.put`（`INSERT`；唯一冲突则重读，同 hash 返回原结果，不同 hash 报错）。
   5. `[COMMIT]`。
3. 提交后 `OperationsJobService.relay_outbox` → `NotificationService.handle_event`。
4. 部分受益人重复/失败不影响其他受益人；返回逐人结果。

**取消报名 → 递补**：
1. `RegistrationService.cancel`：权限 + 状态机：
   - `REGISTERED` / `WAITLISTED` → 正常取消；
   - `CANCELLED` → 返回原结果（幂等）；
   - `CHECKED_IN` / `ABSENT` / `INVALIDATED` → 抛 `IllegalTransition`。
2. `[TX]` 锁 `EventSession` 行；`registration = get_for_update(registration_id)` 复核状态；`registration.cancel(actor, reason, now)`；`RegistrationRepository.save(registration)`（version 条件）；审计被取消记录。
3. 若原状态为 `REGISTERED`：
   - 循环 `next_waitlist_candidates(session_id, after_waitlist_no, limit=50)`，按 `waitlist_no` 升序：
     - `candidate = get_for_update(candidate_id)`；若状态不是 `WAITLISTED` → 下一个；
     - `SeatInventoryPort.reserve_for_promotion(session, outgoing_ticket_type_id, candidate.ticket_type_id, registration.seat_no, now)`：
       - `GRANTED` → `candidate.promote(claim.seat_no)`；`RegistrationRepository.save(candidate)`（version 条件）；发 `RegistrationPromoted`；结束；
       - `TICKET_TYPE_FULL` / `SESSION_CLOSED` / `CANDIDATE_CHANGED` → 下一个；
     - 以 `after_waitlist_no = candidate.waitlist_no` 翻页，直到候选耗尽；
   - 全部不可递补 → `SeatInventoryPort.release(session, outgoing_ticket_type_id)`。
4. 若原状态为 `WAITLISTED`：第 2 步已取消；调用 `registration.refund(now)` 置 `payment_status=REFUNDED`（模拟退款）并 `save`；无计数变化。
5. `OutboxPort.enqueue(RegistrationCancelled/Promoted)`；审计；`[COMMIT]`。
6. 提交后通知取消者与递补者。

### 7.2 10 并发抢最后 1 个名额

1. 10 个请求各自通过幂等检查，进入事务。
2. `SeatInventoryPort.claim` 适配器：
   - `UPDATE event_session SET booked_count = booked_count + 1, version = version + 1 WHERE id = ? AND booked_count < capacity`；
   - `rowcount=1` → `seat_no = booked_count`，`GRANTED`；
   - `rowcount=0` → `UPDATE event_session SET next_waitlist_no = next_waitlist_no + 1 WHERE id = ? RETURNING next_waitlist_no` → `WAITLISTED`（不占名额）；
   - 票种配额满 → `TICKET_TYPE_FULL`（同样进候补）。
3. 唯一索引 `(session_id, participant_id)` 防重复；`CHECK` 防超容量；幂等 key 防重复请求。
4. 结果：1 条 `REGISTERED`，9 条 `WAITLISTED`；`booked_count = capacity`。
5. 适配器层测试：10 线程 + Barrier；断言 1 条成功、`booked_count <= capacity`、候补号 1..9。

### 7.3 创建 → 提交审核 → 审核 → 发布 → 修改重审

1. `create_draft`：组织者权限；必填校验；`Event(DRAFT)` + `EventSession` + `TicketType`；审计。
2. `update_event`：`before = EventSnapshot.from_event(event, sessions)`；`apply_edit`；`EditReviewPolicy.classify`：
   - 不重审 → 保存；
   - 重审且 `PUBLISHED` → 保存并回 `PENDING_REVIEW`，从查询隐藏；已有报名保留。
3. `SessionManagementService` 的 6 个结构性写方法（加/改/删场次、加/改/删票种）统一走 `_apply_structural_change`：
   - 取 before；执行写；取 after；`EditReviewPolicy.classify`；
   - `PUBLISHED` 且需重审 → `event.status = PENDING_REVIEW`；审计 `EVENT_WITHDRAWN_FOR_REVIEW`；
   - 调用 `Event.sync_derived(sessions)` + `EventRepository.save_derived(...)` 更新起止时间与最低价；
   - `update_session` 改容量走 `SeatInventoryPort.resize`；`update_ticket_type` 若 quota 调高，触发一次递补扫描。
4. `submit_for_review`：`DRAFT|REVIEW_REJECTED` → `PENDING_REVIEW`；`EventPublishabilitySpec` 校验至少 1 场次、每场至少 1 票种、必填、时间合法、`capacity >= booked`；`revision += 1`。
5. `approve/reject`：管理员；`PENDING_REVIEW` → `PUBLISHED|REVIEW_REJECTED`；通过写 `published_at`；不通过必须给理由；通知组织者。
6. `unlist/relist`：只改 `visibility`，不改 `status`；单独审计。
7. 所有场次结束 → `finish` → `ENDED`。

### 7.4 扫码签到

1. `CheckInService.scan(raw_code, session_id, actor)`：
   1. `QrCodec.verify`：HMAC 常数时间比较；失败直接拒绝（不查库）。
   2. `token.session_id != session_id` → 拒绝。
   3. 查 `AccessRepository.is_assigned(session_id, actor.user_id)`，填入 `inspector_assigned`；`AccessPolicy.require(CHECKIN_SCAN)`。
   4. `[TX]` `RegistrationRepository.get`：
      - `CHECKED_IN` → 幂等返回 `ALREADY_CHECKED_IN`；
      - `REGISTERED` → `registration.check_in_now(inspector, SCAN, now)`；`RegistrationRepository.save` 级联保存 `CheckIn`（version 条件）；审计；`[COMMIT]`。
      - `WAITLISTED/CANCELLED/INVALIDATED/ABSENT` → 拒绝（ABSENT 提示走补签）。
   5. 并发双扫：`UNIQUE(registration_id)` + 乐观锁；第二条返回已签到。
2. 补签：`make_up` 守卫 `now <= session.end_at + 2h`、状态 `ABSENT`、检票员已分配；`ABSENT → CHECKED_IN` 受控转换（`TransitionOverride.MANUAL_CHECK_IN`）；写 `CheckIn(method=MAKEUP, note=reason)`；审计。
3. 签到不更新任何 `event_session` 计数器；统计走 `ReportingReadPort` 的 COUNT。

### 7.5 取消活动

1. `EventLifecycleService.cancel_event(event_id, reason, actor)`：
   1. 组织者本人权限；加载活动 + 场次。
   2. `Event.assert_cancellable(now, earliest_session_start)`：状态 ∈ `{DRAFT, PENDING_REVIEW, REVIEW_REJECTED, PUBLISHED}`；若 `PUBLISHED`，要求 `now < earliest_session_start`（保守规则：任一场次已开始即不可取消）；`ENDED/CANCELLED` 拒绝。
   3. `[TX]` `Event.cancel()`；`RegistrationInvalidationPort.invalidate_for_event(...)`：
      - `REGISTERED` → `INVALIDATED`；`payment_status=PAID` → `PaymentGateway.refund(payment_ref)` → `REFUNDED`；
      - `WAITLISTED` → `INVALIDATED`；`payment_status=PAID` → `refund` → `REFUNDED`（候补的 `payment_ref` 由工厂生成，退款为模拟状态翻转，无真实资金流）；
      - 终态 → 跳过，不重复退款。
   4. 每个场次 `SeatInventoryPort.reset(session_id)`（`booked_count=0`、各票种 `sold_count=0`）。
   5. `OutboxPort.enqueue(EventCancelled(...))`；审计（含影响条数/退款数）；`[COMMIT]`。
2. **不因报名量拒绝取消**。原型单事务处理全部报名（需求规模 ≤5000）；超过 5000 仅记录性能告警，可选启用 OPTIONAL 的游标分批任务。
3. 提交后 `NotificationService.handle_event(EventCancelled)` → `event_affected_user_ids` → 逐用户发消息（去重键 `event:{id}:cancelled:{user_id}`）。

### 7.6 定时任务

| 任务 | 频率 | 幂等依据 |
|---|---|---|
| `AttendanceJobService.settle_finished_sessions`：`REGISTERED → ABSENT`；`WAITLISTED → CANCELLED(SESSION_ENDED)` 且 `PAID → REFUNDED`；写 `settled_at` | 1 分钟 | `settled_at IS NULL` + 状态守卫；`ConcurrencyConflict` 重读后跳过已签到 |
| `AttendanceJobService.close_finished_events`：所有场次结束 → `Event.ENDED` | 1 分钟 | 状态守卫 |
| `NotificationService.send_sale_reminders`：`PUBLISHED`、`LISTED`、`sale_start_at ∈ (now, now+1h]`；收藏者逐人发消息 | 5 分钟 | `dedupe_key` 唯一；失败不写 dedupe，下一轮重试 |
| `OperationsJobService.relay_outbox`：投递未发布事件 | 10 秒 | `published_at IS NULL` + `attempts` 退避 |
| `OperationsJobService.backup`：每日备份 | 每日 | `backup_run`；失败告警重试 |

## 8. 状态机

### 8.1 活动

| 当前 | 允许 | 触发/守卫 |
|---|---|---|
| `DRAFT` | `PENDING_REVIEW` / `CANCELLED` | 组织者；必填完整；至少 1 场次 1 票种 |
| `PENDING_REVIEW` | `PUBLISHED` / `REVIEW_REJECTED` / `CANCELLED` | 管理员审核；组织者取消（未开始） |
| `REVIEW_REJECTED` | `PENDING_REVIEW` / `CANCELLED` | 组织者重新提交/取消；**不可直接发布** |
| `PUBLISHED` | `PENDING_REVIEW`（实质性修改）/ `ENDED` / `CANCELLED` | `EditReviewPolicy`；所有场次结束；`now < earliest_session_start` |
| `ENDED` / `CANCELLED` | 无 | 终态 |

`Visibility: LISTED <-> DELISTED` 与 `status` 正交；下架不改状态；查询条件 `status ∈ {PUBLISHED, ENDED} and visibility=LISTED`。

### 8.2 报名

| 当前 | 允许 | 守卫 |
|---|---|---|
| `WAITLISTED` | `REGISTERED`（递补）/ `CANCELLED`（本人或场次结束）/ `INVALIDATED`（活动取消） | 场次未结束；按候补号；活动取消系统作废 |
| `REGISTERED` | `CHECKED_IN` / `ABSENT` / `CANCELLED` / `INVALIDATED` | 验签+分配；场次结束未签到；本人；活动取消 |
| `CHECKED_IN` | 无 | 终态 |
| `ABSENT` | `CHECKED_IN` **仅补签**（2h + 分配 + 审计，`TransitionOverride.MANUAL_CHECK_IN`） | 唯一受控例外 |
| `CANCELLED` / `INVALIDATED` | 无 | 终态 |

取消分支：
- `REGISTERED/WAITLISTED` → 取消；
- `CANCELLED` → 幂等返回 `ALREADY_TERMINAL`；
- `CHECKED_IN/ABSENT/INVALIDATED` → 抛 `IllegalTransition`。

支付状态（仅两值）：
- 新建报名（含候补）：`PAID`（模拟支付），`payment_ref = "sim:{registration_id}"`。
- 递补：保持 `PAID`。
- 用户取消 `REGISTERED`：不退款，保持 `PAID`。
- 用户取消 `WAITLISTED`、场次结束关闭候补、活动取消：`PAID → REFUNDED`（模拟状态翻转，无真实资金流）。
- 活动取消的 `REGISTERED`：`PAID → REFUNDED`。

## 12. 数据、索引、事务与安全

### 12.1 关键表与索引

- `event(status, visibility, start_at)`；`event(location, start_at)`；`event(min_price)`；`event(organizer_id)`。
- `event_session(event_id)`；`event_session(end_at, settled_at)`。
- `registration(session_id, status)`；`registration(participant_id)`；`registration(event_id, status)`；`registration(session_id, waitlist_no)`。
- `check_in(registration_id)` UNIQUE。
- `notification_message(user_id, created_at)`；`notification_message(user_id, type, dedupe_key)` UNIQUE。
- `audit_entry(at)`；`audit_entry(actor_id)`；`audit_entry(target_type, target_id)`。
- `favorite(event_id)`；`favorite(user_id)`。
- `evaluation(session_id, participant_id)` UNIQUE。
- `idempotency_record(actor_id, scope, key)` UNIQUE。

派生字段：`Event.start_at/end_at/min_price` 由 `SessionManagementService` 在场次/票种变更后调用 `Event.sync_derived` + `EventRepository.save_derived` 落库；草稿无场次时为 `NULL`；搜索过滤 `start_at IS NOT NULL`。`EventRepository.save` 不写这三个字段，避免与派生逻辑双写。

查询形状：活动搜索用单条 SQL join（event + event_session + ticket_type 聚合 + user），固定 20 条，不加载领域聚合；`EventCardView` 直接投影；无 N+1。关键词 `LIKE '%kw%'` 同时匹配 `event.title` 与 `user.display_name`，其余条件 AND。排序按 `SortSpec` 顺序生成多列 `ORDER BY`，白名单校验；分页越界返回空页。

### 12.2 事务边界

| 用例 | 事务范围 |
|---|---|
| 报名 | 幂等记录 + 席位 claim + 报名 + 发件箱 + 成功审计 |
| 取消报名 + 递补 | 取消 + 锁候选 + reserve_for_promotion + candidate.promote/save + 发件箱 + 审计 |
| 创建/编辑/提交 | 活动 + 场次/票种 + `save_derived` + 审计 |
| 审核/发布 | 活动状态 + 审计 + 发件箱 |
| 取消活动 | 活动 + 全部报名失效/退款 + 场次计数归零 + 发件箱 + 审计 |
| 扫码签到 | 报名状态 + 签到 + 审计 |
| 缺席结算 | 单场次：报名批量 + `settled_at` + 审计 |
| 开票提醒 | 单活动：消息批量 + 去重键 |
| 发件箱投递 | 单事件：`handle_event` + `mark_published/mark_failed` |
| 导出 | 导出记录 + 审计（文件生成可重试） |

失败审计：先 `uow.rollback()`，再 `AuditService.record_failure`（独立连接/事务，重试 2 次，失败落本地文件并告警）。成功审计在业务事务内，写失败则业务回滚（fail-closed）。

### 12.3 安全、可靠性与可用性

- 密码：PBKDF2/bcrypt 加盐哈希；8 位以上且字母+数字；5 次失败锁 15 分钟；会话 30 分钟闲置；token 存哈希。
- 二维码：报名编号 + `nonce` + HMAC；服务端常数时间验签；非本场次/伪造/失效拒绝。
- 日志：主表只追加，不提供删除/修改接口；保留 ≥365 天；超期记录由运维**归档**到只读归档表/文件，主表不删除；审计投递 at-least-once，`audit_id` 幂等。
- 备份：每日 SQLite 备份；失败告警 + 重试；恢复后唯一索引防重复。
- 时区：全链路 UTC aware；展示层转本地时区。
- 并发：SQLite `WAL`；写事务短；10 线程测试 + Barrier；容量条件更新。
- REQ-020 测量口径：10 轮 × 每轮 10 个并发请求抢最后 1 个名额；成功 = 返回 2xx 且结果正确；失败/超时计入分母；可用性 = 成功次数 / 总请求数 ≥ 99%；记录每轮事务持有时长。
- REQ-019 测量口径：1000 活动/5000 报名；单用户连续 100 次查询；≥95 次 <0.2s；失败/超时计入未达标。

## 13. 三方案取舍与最终裁定

| 主题 | 采纳 | 裁定理由 |
|---|---|---|
| 模块划分 | A 的 8 业务模块 | 最贴 lab2 报告要求，能画组件图/包图 |
| 聚合边界 | B 的 Event / EventSession / Registration | 抢票只锁场次行，审核不锁名额 |
| 名额一致性 | B 的单行账本 + A 的直接转让 + C 的窄端口 | 单一写者、无释放窗口、可测试 |
| 依赖纪律 | C 的 domain 零 I/O + 端口反转 | 可脱库测试，模块无环 |
| 规则对象 | C 的状态机/策略/权限 | 易变规则集中，扩展是加法 |
| 审计 | A 的成功/失败双通道 + B 的独立事务 | 满足 REQ-016“失败也记录” |
| 取消活动 | A/C 的同步批量（不拒绝） | REQ-004 无数量上限；原型规模可行 |
| 通知 | A 的事件→消息映射 + B/C 的叶子模块 | notification 不反向依赖业务模块 |
| 读模型 | 三方案共识：不建投影 | 1000/5000 规模用索引足够 |
| 支付 | A 的两值口径 | REQ-004 只允许 PAID/REFUNDED；候补也 PAID（模拟） |
| 角色 | 四角色 + 场次授权 | 符合 REQ-015 原文与“未分配不能操作” |

**明确不采用**：
- 7 个限界上下文、`Occurrence` 命名、上下文契约包（B R1）——改为 8 模块。
- 35 个端口、30 个用例类、通用 `Specification` 组合子（C R1）——合并为约 22 个端口、15 个服务。
- 60+ 类、`ReviewRound`、`NotificationSourcePort`、`UoW.collect`、投影/对账/流程管理器——删除或降为 OPTIONAL。

## 14. 已知取舍与风险

1. **活动取消同步事务**：原型单事务处理全部报名；5000 条以内可接受。超大活动（>5000）只有性能告警，没有可运行的异步降级（OPTIONAL）。报告中如实说明。
2. **`Event`/`EventSession` 拆聚合**：跨聚合不变式（至少 1 场次、场次时间 ⊆ 活动时间）由应用服务在 `submit/update/remove` 校验，数据库兜底；漏一处会出错，需集成测试覆盖。
3. **`booked_count` 是快照**：唯一写入者是 `SeatInventoryPort`；`save_metadata` 显式列清单禁写计数。lab3 第一天应写“改容量并发报名”的双线程测试。
4. **票种名额与候补**：按 `waitlist_no` 分页扫描，票种满跳过；被跳过者保留序号，票种 quota 调高时触发一次递补扫描。需单测“VIP 满/普通有空/队首 VIP”场景。
5. **参与者取消不退款**：REQ-007 未要求；只有活动取消退款。候补记录按模拟支付置 `PAID`，取消候补置 `REFUNDED`，报告中解释“无真实资金流”。
6. **补签例外**：`ABSENT → CHECKED_IN` 是状态机唯一受控转换，必须带 `TransitionOverride.MANUAL_CHECK_IN`、2h 窗口、检票员分配、审计。
7. **`AccessPolicy` 纯函数**：服务必须先查 `is_blacklisted`/`is_assigned`/`has_checked_in` 填入 `AccessContext`；漏填会导致规则误判，需用例级测试覆盖。
8. **`promote` 的唯一写者**：`SeatInventoryPort.reserve_for_promotion` 只改计数；`Registration.promote` + `RegistrationRepository.save`（version 条件）改报名状态。任何字段只有一个写者。
9. **UI 16 屏**：为 lab2 报告提供界面清单；具体视觉设计后续用 UI 工具完成。
